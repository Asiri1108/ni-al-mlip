    1. cmdargs need '-k on g 1 -sf kk -pk kokkos neigh half newton on' (not
       'neigh full newton on', which this LAMMPS version rejects: KOKKOS
       requires newton off with neigh full, but pair_style mliap itself
       requires newton pair on -- neigh full is simply incompatible with
       mliap here; half+on is the working combination) and
       activate_mliappy_kokkos()/load_unified_kokkos() (not the plain
       non-kokkos functions).
    2. The Kokkos GPU-array coupling (mliap_unified_couple_kokkos.pyx)
       hard-requires `cupy` (zero-copy GPU array wrapping of Kokkos device
       pointers) -- not installed, caused a NameError. Installed
       cupy-cuda12x into the target venv.
    3. lmp.finalize() segfaults in-process (Kokkos::Cuda::finalize()
       conflicting with torch+cupy's own live CUDA contexts) -- confirmed via
       PYTHONFAULTHANDLER traceback that this happens strictly AFTER `run 0`
       completes and results are already extracted, i.e. it's a teardown-only
       bug, not a compute bug. Script no longer calls lmp.finalize() (harmless
       to skip for a one-shot-per-process script).
    4. (Not a bug, a real quirk) extract_atom("f"/"id") under the Kokkos
       array layout returns nlocal+nghost rows (826 vs 16 real atoms here --
       periodic ghost copies within the 6 Angstrom cutoff), not just owned
       atoms. Owned atoms are confirmed to occupy the first `natoms` rows in
       read_data order (atom_modify sort disabled, single process) --
       verified explicitly via id check, not assumed.

POST-BUILD FIXES (2026-08-19, same day)
  1. `lmp` binary initially failed with "liblammps.so.0: cannot open shared
     object file" -- CMake install set an empty runtime path (no RPATH) for
     the executable. Fix: run with LD_LIBRARY_PATH=<prefix>/lib. This is a
     runtime environment requirement, not a rebuild; documented here so it
     is not rediscovered as a mystery failure later.
  2. Python `lammps` module was never installed by the default `cmake --build .`
     -- `install-python` is a separate, non-ALL CMake target (only runs via
     `make install-python` / `cmake --build . --target install-python`), not
     included by the plain build. Ran it explicitly; it builds a wheel
     bundling its own copy of liblammps.so (see LAMMPS_PYTHON_MODULE row
     below) and installs into the target venv's site-packages.
